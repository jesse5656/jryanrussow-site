# 1. Purpose

This package contains the minimum operational artifact set required before the
first Institutional Memory Diagnostic pilot may begin.

It converts the pilot architecture into working forms for:

1. qualifying a client;
2. defining scope;
3. requesting evidence;
4. preserving evidence provenance;
5. planning interviews;
6. conducting interviews;
7. reconstructing knowledge traces;
8. developing findings;
9. challenging findings;
10. preparing the executive report;
11. maintaining the findings register;
12. measuring the pilot itself.

This package does not establish that the methodology is commercially or
scientifically validated.

------------------------------------------------------------------------------

# 2. Pilot Authorization Rule

A pilot is not authorized merely because a prospective client is interested.

Before kickoff, the Institute must establish that:

- the client is suitable;
- the problem is sufficiently bounded;
- evidence access is realistic;
- relevant personnel are available;
- the engagement can reasonably fit the pilot economics;
- prohibited or excluded professional work is not being requested;
- and the required operational forms can be completed.

The authorization decision must be recorded.

## Opening Boundary

Explain that the interview supports an organizational diagnostic.

The purpose is not to assign personal blame.

Interview testimony is evidence but may require corroboration.

## Core Questions

### Knowledge

What did you know about the issue?

When did you know it?

How did you learn about it?

Who else knew?

### Institutional Possession

Where was the information recorded?

Where would another person find it?

What depended on personal memory?

### Meaning

How serious did the issue appear at the time?

How was that significance communicated?

### Decision Availability

Who had authority to act?

What information did that person receive?

### Recognition

How was the issue interpreted?

Was it seen as isolated or recurring?

### Escalation

What caused issues like this to be escalated?

What made escalation difficult?

### Corrective Action

What happened after the issue was recognized?

Who assigned action?

### Execution

Was the action actually completed?

How was completion demonstrated?

### Verification

How did the organization know the action worked?

### Learning

What happened if the problem returned?

Did recurrence cause system-level reassessment?

### Formal Systems

What formal processes governed this issue?

How did actual practice differ?

### Capacity

Did staffing, workload, schedule, budget, production, or organizational change
affect the response?

## Counterevidence Questions

What did the organization do well?

Can you identify a similar problem that was successfully recognized and
corrected?

What evidence would contradict the concern being examined?
